# Talent Paths Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every class can follow a recommended talent path for each spec (Druid five) or a custom path of its own, chosen on a polished Talents tab and remembered per character.

**Architecture:** A generated `TalentTreeData.lua` carries the game's full trees; a hand-written `TalentPaths.lua` the researched spec paths; a new `Talents.lua` engine picks the path, builds custom plans, checks the game's rules, encodes share codes and adapts the trainer list. `ns.talentAt` reads the chosen plan, so every existing talent display follows it. The Talents tab moves to `TalentTab.lua`.

**Tech Stack:** WoW: Forever addon (Lua 5.1, `## Interface: 16001`), Python 3 + lupa harness (`tests/run.py`, `tests/wowmock.lua`, `tests/scenarios.lua`), `tools/gamedata.py`.

**Spec:** `docs/superpowers/specs/2026-11-14-talent-paths-design.md`

## Global Constraints

- Lua 5.1: no `goto`, no `//`, no `\u{}`; runtime text ASCII only; no new globals (data on `ns`, frames `LevelingCodex*`).
- Guard `C_Traits` / `C_ClassTalents` and any non-core API with existence checks and `pcall`.
- Works with empty SavedVariables (`ns.settingsLost`), on the minimal client and for the unsupported class (DEATHKNIGHT: no tree, no paths, nothing errors).
- Every clickable has a `codexLabel` (harness + Forever controller).
- `python tests/run.py` passes before each commit (`blocked-report` fails only in worktrees).
- Both .toc files stay byte-identical; new files go in both.
- Path text: our own wording, ASCII, `why` < 240 characters, `note` <= 90; roles: Melee damage, Ranged damage, Caster damage, Tank, Healer.

## Review Focus

- A saved custom path from before a game patch (a renamed or moved talent): the list is cut at the first point that breaks a rule, never a Lua error (Task 3 test).
- `charDB.talentPath` names a key that no longer exists (or another class's key from a copied SavedVariables file): falls back like a missing key (Task 3 and Task 7 tests).
- Pasted share codes with spaces, line breaks, lower case, another class's code or an older tree version: trimmed and case-folded; another class or version refused with the reason, nothing changed (Task 3 test).
- An empty or short custom path at a level-up: chat, banner, This Level card and the talent-window hint say to plan the point; nothing indexes a nil plan entry (Task 4 test).
- Minimal client (no `C_Traits`) and the unsupported class: path choice works, "My current talents" is hidden, the fallback is the guide (Task 3 and Task 6 tests).

### Task 3: Path engine

**Files:**
- Create: `Talents.lua` (after `Guide.lua` in both .toc)
- Modify: `Guide.lua:7-40`, `TalentGuide.lua` (add `ns.traitRanks()` next to `ns.traitLayout`), `tests/wowmock.lua:964-967` (`GetNodeInfo` returns `ranksPurchased = n.rank or 0, currentRank = n.rank or 0`), `tests/scenarios.lua` (`S.talentPathApi`), `tests/run.py` (runs `WARRIOR/{full,minimal}/talent-path-api`, `DRUID/full/talent-path-api`, `DEATHKNIGHT/full/talent-path-api`, steps `["login", "talentPathApi"]`)

**Interfaces:**
- Consumes: `ns.talentTrees`, `ns.TALENT_PATHS`, `ns.D.plan`, `ns.D.train`, `LevelingCodexCharDB.talentPath` (string), `LevelingCodexCharDB.customTalents` (list of names, index 1 = level 10).
- Produces (all safe with no tree/paths):
  - `ns.talentTree() -> tree|nil` (player's class, from `UnitClass`'s token)
  - `ns.talentPaths() -> { path }` (`path = { key, spec, role, note, plan, guide = bool, custom = bool }`, Custom last; `{}` without a guide)
  - `ns.talentPathKey() -> key, how` (`how` = "saved" | "matched" | "default"); `ns.talentPath() -> path`; `ns.setTalentPath(key)` (saves, bumps `ns.talentVersion`)
  - `ns.talentPlan() -> plan` (cached by `ns.talentVersion`); `ns.talentSplit(plan, level) -> { n1, n2, n3 }`; `ns.talentUnplanned(level) -> bool`
  - `ns.talentCanAdd(points, name) -> ok, reason`; reasons exactly: `"Needs N points in TREE (has M)"`, `"Needs PREREQ maxed"`, `"All N ranks taken"`, `"All 51 points placed"`, `"Not a talent"`
  - `ns.customPoints() -> { names }`; `ns.customAdd(name)`, `ns.customUndo()`, `ns.customClear()`, `ns.customFrom(key)`, `ns.customFromLive()` -> `ok, reason`
  - `ns.talentCode() -> "LC1-CLASS-CHECK-RUNS"` (CHECK = 4 base-36 chars hashing the class's talent names in order; RUNS = per run 2 base-36 chars talent index + 1 base-36 char count); `ns.readTalentCode(text) -> ok, reason` (trims, upper-cases; reasons `"This code is for a CLASSNAME"`, `"This code was made for other talent trees"`, `"Not a Leveling Codex talent code"`, or the first rule reason with its level)
  - `ns.trainVisits() -> visits` (Data.lua shape; parallel `spells`/`notes`/`icons`; cached by `ns.talentVersion`)
  - `ns.traitRanks() -> { [lower(name)] = rank } | nil`
- Custom plan entries: `{ name, tree, icon, max, from, to, why = tip, more = "" }`. Match rule: the spec path (guide included) with the most of your live ranks among its first N points (N = points spent), at least 60%; ties keep the earlier path.
