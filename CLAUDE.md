# Leveling Codex: notes for Claude

An in-game companion addon for the fan-made **The Leveling Codex** leveling guides, for
**World of Warcraft: Forever** (Blizzard's 2026 Classic-based client, PC/Mac only).
Published on CurseForge (project ID 1789784).

### Data.lua shape
- `spec` (e.g. "Protection"), `guide` (short guide name).
- `plan[]`: talent plan `{ name, tree, icon, max, from, to, why, more }`. Levels `from..to` each put one point into `name`; ranks add up across entries with the same name. `why` is shown at `from`, `more` on the later levels (falls back to `why` when empty).
- `train[]`: trainer visits `{ level, spells[], notes[], icons[] }`. Spell names carry ranks, e.g. `"Rend (Rank 2)"`.
- `br[]`: tip chapters ("brackets") `{ level, range, title, icon, intro, steps[], stepIcons[] }`.
- `macros[]`: `{ name, title, icon, lo, hi, body, pad, kb, tips[] }`. The same `name` appears in several level-banded versions. `pad` uses Xbox names and may contain arrows (translated at runtime).
- Guide text contains Unicode punctuation and arrows; it always goes through `plain()` / `padText()` before display.

### Modules (load order)
All files share the addon table: `local _, ns = ...`. Cross-module calls go through `ns.x()` **at call time**, so a module may call one that loads later; only values read while a file loads need load order. Never create globals (the harness fails on leaks); allowed: the SavedVariables, `LevelingCodexData`, `LevelingCodexProfessions`, `SLASH_LEVELINGCODEX1`, `BINDING_*`, `LevelingCodex_Toggle`, named frames `LevelingCodex*`.
1. `Theme.lua`: `ns.THEMES` (`forever` teal = default, `codex` gold), `ns.C` = active palette (mutated in place by `ns.useTheme`, so `local C = ns.C` stays valid; `ns.themeVersion` bumps on each switch), `ns.rgba`, `ns.db()`/`ns.charDB()` (never nil), `ns.try` (pcall an API that may not exist), timers `ns.after`/`ns.every` (C_Timer or an OnUpdate fallback), `ns.plain` (ASCII-only text), `ns.money(copper)` ("1g 20s 5c"), `ns.coins(copper)` (the same, each part in its coin's colour), `ns.thousands(n)` ("21,400"), `ns.PADS`/`ns.padText`, `ns.say`, `ns.setIcon`, `ns.fade`/`ns.fadeAccent`, `ns.placeByWindow(card, window, state)` (the talent and crafting cards: above the window, else below, else inside its top edge, clear of bars hanging off its edges, found with EnumerateFrames when it opens and 1 and 3 s later).
1b. `Art.lua` (`ns.art`): Blizzard frame art with fallbacks. `A.FILES` lists every art file; `A.hasFile` probes it once (SetTexture returns false when missing) and every piece falls back to the flat Codex look. Helpers: `A.frame` (adds `BackdropTemplate` when the client needs it), `A.backdrop(f, "dialog"|"tooltip", bg, edge)`, `A.header` (gold title banner), `A.button` (UIPanelButtonTemplate, `SetLabel`/`SetLook`), `A.segment` (a panel button for `U.segments`: lit = the panel art, a 1 px gold inner edge, gold label and the check box's tick `checkTick` when the client has it; unlit = a flat `C.btnOff` plate (the template's `Left`/`Middle`/`Right` art at alpha 0) with a grey label and an accent hover; a template without those pieces dims to alpha 0.6 instead), `A.check` (UICheckButtonTemplate + label), `A.tab` (character-sheet tabs, `SetSelected`), `A.arrow` (spellbook page arrows, `codexLabel` "<"/">"), `A.portrait` (round class icon). `A.report` records what was used, for `/codex debug`.
2. `Guide.lua`: lookups into `ns.D` (this class's guide, set at login): `talentAt`, `trainAt`, `nextTrain`, `bracketFor`, `macrosFor`, `comingMacros`. All cope with `ns.D == nil`.
2b. `Professions.lua`: the profession guides (`ns.P` = `LevelingCodexProfessions`, `ns.PROF_ORDER`). `ns.profSkill(key)` (GetProfessions, else the classic skill list; nil = not learned/unknown; a closed heading in the classic list keeps the last skill seen this session, or returns `nil, nil, true` = "not seen"), `profStep`, `profNext`, `expectedCrafts`/`craftsLeft` (1 per point below yellow, then `(grey - s) / (grey - yellow)`), `profShopping`, `profTier`/`profTierDue` (`"train"`/`"cap"`), `veinColor` (orange < skill+25 < yellow < +50 < green < +100), `profZones` (faction, `All`, Skyborne isle). Parts (Tailoring's bolts): `ns.profPart(key, item)` (the part that makes an item), `ns.profHave(key, item)` (bags plus held parts as their cloth; nil without `GetItemCount`), `ns.profClothFor(key, step)`; `profShopping` never lists a part: what's still needed becomes its materials, rows carry `via = { part, n }` (parts still to make, their own steps included). Skill-ups (SKILL_LINES_CHANGED / CHAT_MSG_SKILL / TRADE_SKILL_UPDATE, else a 1 s poll) are compared with the last reading this session: `ns.profCardRows` -> `ns.showCard` only at a new step, a tier due, a cap, a new vein (`db.noProfCards`; the card's subtitle is your tier). `ns.profLevelRows(level)`: training a level-up opens (skill already there), as rows for the level-up banner and chat. TRAINER_SHOW records requirements that differ from the guide's `learn` (`ns.trainerDebugLines`). Rods (Enchanting): `ns.profRod(key, step)`, `ns.profHasRod(key, rod)` (that rod or a better one in your bags, by mask without the bit library; nil without `GetItemCount`).
2c. `Disenchant.lua`: the disenchanting table and your bags: `ns.deBand(key, level)` (required level), `ns.deNeeded(key, step)` (the step's band materials, through parts), `ns.deBagItems(key)` (green/blue/epic weapons and armour from bags 0-4 via `C_Container` or the classic calls and `GetItemInfo`; green armour dust then essence, weapons the reverse, blue/epic the shard; unloaded items skipped; nil without the APIs).
3. `Macros.lua`: `ns.setupMacros(onlyExisting)`. A macro is "ours" if it's in `LevelingCodexCharDB.made` **or its body matches a guide version** (so auto-update survives lost SavedVariables). Combat: a manual setup is queued as "full", a level-up refresh as "refresh" (never creates macros). Failures open the copy box.
4. `Banner.lua`: level-up chat (`ns.levelUpMessage`) and the banner (`ns.showToast(level, force, test)`, `ns.showCard(title, sub, rows, onClick, target)` for other cards shown right away; both set `ns.lastBanner` (`{ tab, key, level, at }`): `ns.toggleWindow` opens that within 60 s, once (`ns.openTab` clears it), `ns.setToastUnlocked`, `ns.placeToast`, `ns.getToast`, `ns.dropToast`).
5. `Window.lua`: the `/codex` window: pooled widgets (`take`/`releaseAll`), drawing helpers (`T`, `rect`, `box`, `icon`, `btn`, `chip`), `renderers[tab]` (level/talents/trainer/macros/tips/settings), per-tab scroll memory, the talent tree (`talentModel`, `layoutTree`: game layout from `ns.traitLayout()` else tiers from the plan), controller/keyboard drawing (`parsePad`, `padCombo`, `keyCombo`, `controllerMock`, `keyboardMock`; glyphs on the `top` layer above icons), `ns.rebuildForTheme`, `ns.openTab`, `ns.toggleWindow`, the copy box `ns.showMacroCopy(m, list)`, Esc/controller close. Other files add tabs with `ns.addTab(key, label, renderer)` (before Settings) and draw with `ns.ui` (`W`, `T`, `rect`, `box`, `plate`, `icon`, `btn`, `check`, `hit`, `sectionTitle`, `goldRuleAt`, `refresh`, `segments`, `fold`). `U.segments(x, y, w, labels, lit, onPick, tips)` draws one row of choices (24 px, equal widths 4 px apart; each a pooled `A.segment` with `codexLabel` = its label and `codexOn` on the lit one; returns 24); `U.fold(open, x, y)` the quest log's plus/minus (`plusUp` / `minusUp`, 16 px; "+" / "-" without the art); `hit`'s 8th argument `label` is its `codexLabel` (nil clears it). `T` turns word wrap back on for every pooled string (a caller may keep one to a line with `SetWordWrap(false)`).
5b. `ProfessionTab.lua`: the Professions tab: profession switch (one button per `PROF_ORDER` entry), your skill, the step to do now (or one clicked in the route) with materials against your bags, the training card, the route, the shopping list to 300, veins with zones, camp objects, the cloth section (Tailoring: mob levels and zones, your step's cloth first and marked; bolt lines on the step card; shopping rows "for N bolts, you have H"). Enchanting: the rod line (you have it / you need it), the disenchanting section (bands, your step's marked, the essence line, up to 8 bag items). `ns.profTabShow(key)`.
5c. `Gamepad.lua` (`ns.gamepad`): controller support for the Codex's frames. `attach(frame, { main, popup, scroll, focusables, onTab })` hooks OnShow/OnHide and the frame's OnGamePadButtonDown (B/Back close, LB/RB `onTab`); each show picks a mode: nil (controller not in use: `InputUtil.IsGamepadUIEnabled()` / `IsUsingGamepad()`), `"forever"` (joins Forever's navigation: `GamepadMode.FrameControlsManager:FrameShown/FrameHidden`, `SmartNavigation:SetScrollFrameForFrame` / `RefreshButtonGroups`, `SmartNavigation_MarkFrameIgnored` on `padSkip` widgets) or `"codex"`, the backup (manager missing, FrameShown errors or returns false, no focus inside the frame 0.5 s later, or `db.padNative == false` from Settings > Controller): the gold highlight `LevelingCodexPadFocus` (`.target`), D-pad up/down = nearest row then closest across, left/right = same row, A clicks (EditBox: focus), right stick (`OnGamePadStick` "Right"/"Camera") scrolls, focus shows the piece's tooltip, content pieces scroll into view (header and tabs are `fixed`). PLAYER_REGEN_DISABLED lets go of the controller and remembers the highlight; `repick()` after the setting changes. Out of combat only (a frame shown in combat is set up at PLAYER_REGEN_ENABLED); GAME_PAD_ACTIVE_CHANGED re-picks. Window.lua tags its pooled widgets at the end of every redraw, from what they are then: `padSkip` = no OnClick, `padX`/`padY` = centre in content coordinates from the TOPLEFT anchor. Forever mode marks tooltip-only pieces before FrameShown, and after a redraw moves Forever's focus back onto the window (`SelectTopLeftButton`) when it was left on a hidden or skipped piece; LB/RB only act while the Codex is Forever's active frame (`GetActiveFrame`). PLAYER_REGEN_DISABLED (before lockdown) releases propagation on every frame and hands Forever-mode frames back (a hand-back held up by combat is sent at PLAYER_REGEN_ENABLED). The right stick keeps the highlight on a piece in view. `refresh(frame)` after every redraw; `debugLines()`.
6. `Minimap.lua`: `ns.updateMini` (the button: `ns.ADDON_ICON` = the Level 60 badge, default angle 10, right side) and, once per session, an entry in Forever's addon compartment (`AddonCompartmentFrame:RegisterAddon`; left-click toggles, right-click settings).
7. `TalentGuide.lua`: 0.25 s ticker. Shows only while there are unspent points (`C_Traits` tree currency, else `UnitCharacterPoints`; unknown = show) and traces the next unspent point in the plan (`10 + points spent`). The trace copies the button's own border art (`StateBorder`/`Border`/... atlas or file) so it matches circle/square/choice nodes; with only a mask it draws a round glow, else a box. Finds the window (`TALENT_ROOTS`, then window-sized frames named `*Talent*`/`*Trait*` found by `discoverRoots` on toggle hooks and talent-addon loads), then the button by name (trait APIs) or icon. Once found it only re-checks the cached button (pooled buttons get reused); misses back off up to 8 s. Hides on the window's `OnHide`. Never treat `LevelingCodex*` frames as a window.
7a. `ProfessionGuide.lua`: the crafting window guide (`db.noCraftGuide`). Active from TRADE_SKILL_SHOW until TRADE_SKILL_CLOSE (else polling; the event may come before the window shows, so it re-discovers windows for 10 s). Finds the window (`TradeSkillFrame`, `ProfessionsFrame`, `CraftFrame`, then discovered `*TradeSkill*`/`*Profession*` frames, never `LevelingCodex*`), the profession (`GetTradeSkillLine` or `C_TradeSkillUI.GetBaseProfessionInfo`, "Smelting" = Mining), the recipe (`GetTradeSkillInfo`, then `C_TradeSkillUI.GetRecipeInfo`: colour, numAvailable; the classic list only holds what the window shows) and its row by text (colour codes, `[N]` counts and padding stripped; a button first, never the details pane; while it's out of view the search backs off 0.5, 1, 2 s). Hides on the window's `OnHide`. Not in the list: `IsPlayerSpell` tells "filtered" from "not learned" (with the step's alternative). **Read-only: never select, scroll or click in the crafting window** (an automatic select/scroll/row-click, and the old Show it button, took Forever's list away from the controller; `craftHandsOff` checks it on the classic, retail and ScrollBox windows). Outlines the row (`LevelingCodexCraftTrace`, no mouse) and shows `LevelingCodexCraftHint` (text only, no mouse; not learned / grey: next step / "scroll to it" while the row is out of view). Pick order: rod first (`rodFirst`: the step's `rod` is missing by `ns.profHasRod` == false and both the rod's recipe and the step's are in the window; card "Make your Runed X Rod first: every enchant from here needs it."), then parts first, then the step; rod and part picks skip the grey branch and the colour prefix. Tailoring: bolts first (`partFirst`, count = dust per craft times what one craft makes, so Motes make 3): when the step needs a part (`ns.profPart`) you have too few of for one craft, you have the cloth for one, and the part's recipe is in the window, the pick is the part (card: "Make Bolts of X first: your N X make M.", grey doesn't stop it); otherwise the step. Mining picks the step's smelt you can know with the best chance (counted only while orange, else its chance; none: "mine instead" and when the next smelt opens). `ns.craftDebugLines`.

Quest modules in .toc order:

- `QuestData.lua` defines the allowed global `LevelingCodexQuests`. Each section is playable independently and displays its verification state.
- An opportunistic item-started quest has `startItem = itemID` on its quest metadata, copied to every step. The guide waits for that item in the player's bags or for the quest to enter the log. The accept step's `item` separately provides the use button. Bag events only recalculate when the presence of a tracked starter item changes.
- `QuestAlternateData.lua`, the three 30-60 route files, `QuestDungeonData.lua`, `QuestDungeonData3060.lua`, `QuestSpecialData.lua` and the `QuestHorde*.lua` files use `QuestData.lua`'s temporary `build` helpers (`tools/questroute.py` reads the quest data files from the .toc, QuestData.lua through QuestClassData.lua). A `note` step may carry `drop = { questIDs }`: quests the player abandons there (grey dungeon pickups from an earlier band); the route audit removes them from its simulated quest log. The audit also retires a `forDungeon` pickup once the route is past that dungeon's last level + 3, because its hand-in lives in the dungeon guide. `QuestClassData.lua` consumes them last; its final block sets each special and class guide's `reward` (what finishing it gives you, shown under its title in Quests > Guides and as "You get: ..." on its page) from a `REWARDS` table by section id (a guide's own `reward` wins; sources in `tools/audits/2026-11-13-guide-rewards.md`; `quest_reward_checks()` fails a non-ASCII line, one over 60 characters or ending in a period, a reward on another kind of guide, or a `REWARDS` id that names no guide). Short class quests may be inserted after a named step. Longer chains are `side` sections with a class and optional race filter. Show class quests applies to class sections, and Missed quests can show an available class pickup even when it is grey.
- Dungeon and special guides are opt-in `side` sections with `category = "dungeon"` or `"special"`. The quest engine bookmarks the leveling route while a detour is active. Finishing or using Return to leveling resumes it. Dungeon steps have `phase = "prepare"`, `"inside"`, or `"after"`. The entry step (`type = "dungeon"`) is done while you're inside, and also once a later step of its guide is done (a run finished before the guide could see you enter). The checklist can start at any phase. An `instanceID` enables automatic entry detection, with an English name fallback when the client omits the ID. Use `uncertain` for live verification notes (data only: players never see them, like `verified`), `links` for related guide IDs, and a step's `guide` to link an outdoor step to a detour checklist (`withGuide(id, step)` in QuestData.lua, or `guide =` in an action's extra table; the step window offers Plan <guide> while it is current). A dungeon may list `bosses = { { name, tip, npc?, encounter? } }` (ASCII, own wording; `encounter` = the client's DungeonEncounter ID, which ENCOUNTER_END reports, checked by `questroute.py audit` against `quests.instances` in the reference; names may differ from the game's internal encounter names, e.g. Magmatus = "Infurnus"), shown as BOSSES IN ORDER on its library page. Boss steps: `buildRoute` (`addBossRows`) puts one row per boss (`type = "boss"`, key `<id>:boss:<n>`, the tip as text, phase inside) after the guide's last inside step, and marks its inside `complete` rows `row.sticky` (shown as On the way under the boss; passOver/stickies/upcoming read `row.sticky` like `step.sticky`). A boss row is pending only while `inDungeon(section)`; `Q.bossDown(encounter, name, npc)` (QuestGuide: ENCOUNTER_END with success, BOSS_KILL; never the combat log, see the client facts) marks it done; Next passes it. Dungeon ahead: `buildRoute` puts a `type = "plan"` row (key `<section>:plan:<run>`, the next step's map spot and `pos`) before the route's first step for each run: a step tagged for it, or the accept of a quest some tagged step needs (`runOwn[run]`; lead-in chains the checklist also copies, like the Defias Brotherhood, don't count). It is pending only while `not Q.planDecided(id)` (no per-run choice and not Plan every dungeon run), you haven't passed it in that section (`later`), you haven't outleveled the run or turned in one of `runOwn`; `Q.planText` explains it. The step window offers Plan <dungeon> and labels Next "Skip" (Q.next sets the plan to false and says so); the Quests tab has Plan <dungeon> / Skip this run (`ns.planQuestRun`, which also leaves Back's review via `Q.leaveReview`). A ready run (`Q.readyRun`) leads the step text with "Find a group for <dungeon>". Dungeon plans: an outdoor step tagged `forDungeon(step, "dungeon-<id>")` (`optional = true`, `dungeon = section id`; the audit checks the id) shows only while `Q.planned(id)` (`db.questDungeonPlan[id]`, else `db.questDungeons` = Settings > Plan every dungeon run; the library has Plan recommended/all/none and a per-dungeon toggle). ## WoW: Forever client facts (design around these)
- **Forever redrew the Eastern Plaguelands map** (QuestieDB Forever: Tirion 5.2, 35.6; classic 7.6, 43.7; roughly x' = 0.899x - 1.58, y' = 0.898y - 3.65). Use the Forever QuestieDB coordinates there, never classic ones. No other 30-60 map differs between the two flavours (Stormwind Keep moved too).
- `## Interface: 16001`. **Lua 5.1** (WoW flavour): no `goto`, no `//`, no integer division, no `\u{}` escapes.
- Talents use retail's **C_Traits** trait system. `GetTalentInfo`, `GetNumTalentTabs` and the Spec APIs **do not exist**. Talent window frame/button names are **unconfirmed**: keep the multi-strategy finder (known names, discovered frames, match by name then icon).
- Registering an unknown event **throws and aborts the file**: `pcall` `RegisterEvent` for anything beyond the core events.
- **Secret values.** Forever hides some numbers from addon code (your speed in flight from `GetUnitSpeed`, ...): `tonumber`, `math.*` or arithmetic on one is blocked ("numeric conversion on a secret value", a Lua error). Check `issecretvalue(v)` (may be missing on other clients) before using a number that could be secret. The mock's `MOCK.SECRET` stands for one (`tonumber` refuses it; `MOCK.runSpeed`).
- **The combat log is Blizzard-only.** `RegisterEvent`/`UnregisterEvent("COMBAT_LOG_EVENT_UNFILTERED")` from an addon is blocked even inside `pcall` (the "LevelingCodex has been blocked from an action only available to the Blizzard UI" dialog, function `UNKNOWN()`). Never touch it.
- **Blocked calls are recorded.** Init.lua listens to ADDON_ACTION_FORBIDDEN / ADDON_ACTION_BLOCKED (synchronous: `debugstack` still holds the call) and keeps the last 10 in `LevelingCodexDB.blocked` with the Codex lines below the first `[C]` frame (`where`, e.g. `QuestGuide.lua:1325 < QuestGuide.lua:1378`), said once in chat and listed by `/codex debug`. taint.log stayed empty for these, so ask the owner for that chat line.
- SavedVariables are written on exit but **may not be loaded back** (beta reports). Everything must work with an empty DB; never build a feature that depends on persistence.
- Secure snippets fail. `ReloadUI()` is protected. Reading auras in combat throws.
- Macros: max **255 characters** per body, **16** per name. Macros **skip** unlearned spells but **stop** on a learned spell that isn't ready ("You can't do that yet"). `/castsequence` **stalls** on a not-ready or unlearned step; `reset=N` counts from the last press.
- The game font can't draw `→ ↑ — ×` and similar: **all runtime text must be ASCII** (route guide text through `plain()`).
- Missing texture paths render **green**: always use `setIcon`, or check `SetTexture`'s return value and fall back.
- Assume any non-core API may be missing: guard with existence checks and `pcall`.

- Profession scenarios: `skills:BS;87;150,MI;140;225,TA;150;225:professions` sets skills (BS, MI, HE, TA, EN) (`skilllines` = only the classic skill list; `skillsClosed` / `MOCK.skillsCollapsed` closes its heading); `MOCK.setSkill` fires the skill events; `makeCraftWindow[:retail]` builds a crafting window (`MOCK.trade`); `MOCK.trainer` feeds TRAINER_SHOW (entries may add `rank`, `category`, `cost`; `MOCK.tradeskillTrainer`, `MOCK.money`); `MOCK.bagItems` fills bag 0 for the disenchanting list (`C_Container`, `GetItemInfo`; `loaded = false` = not cached).
- **Game checks** (`game_checks()`, via `tools/gamedata.py audit` and the committed `tools/reference/forever.json`): fail on a talent that isn't in the class tree, a wrong tab or rank count, a point spent before its row is open or its prerequisite is maxed, a trainer rank that doesn't exist or isn't trainable yet, a macro spell the class doesn't have or a `/castsequence` step learned after the macro's first level. Warn on levels in guide text like "Swipe (16)" that differ from the game, icons that differ, spells listed earlier than the game teaches them. Professions (`audit_professions`): fail on a recipe not on the skill line, colours/reagents/spell that differ, a step that goes grey before it ends, gaps between 1 and 300, a tier that can't be trained before the previous cap; warn on mostly-green steps, icons, `learn` after a step starts, a step naming a recipe the game has more than once, a "trainer" step whose recipe comes from a plan, a `learn` that differs from its plan's skill, "Known when you learn" that doesn't match `auto`, points per craft other than 1. Parts are checked like recipes; a cloth no recipe uses fails; so does a step material the profession makes that no part or earlier `makes` provides; a step's `rod` that isn't its recipe's `tool`, a rod's category/mask that differs, and a disenchant material no recipe uses. `tool_checks()`: `update`/`audit` and the daily report include the profession audit.

## Working rules
- Run the harness before every commit. It must pass with no Lua errors, no non-ASCII runtime text and no leaked globals.
- When a bug is reported from the game, first add a scenario that reproduces it.
- **Guide facts come from the game, not memory.** Before changing a talent reason, macro or trainer line, check it with `python tools/gamedata.py spells|tree|review|packet CLASS`. After a Forever patch or hotfix (or a Game data PR), follow `tools/UPDATING.md`.
- **In-game testing: install straight into the owner's game, never hand over a zip.** After the harness passes, run `python tools/install.py`. It copies the build into `C:\Program Files (x86)\World of Warcraft\_forever_\Interface\AddOns\LevelingCodex` (override with an argument or `LEVELINGCODEX_ADDONS`), removes stale `.lua`/`.xml` from older builds, leaves other files alone and verifies every copy. The installed .toc files get `git describe` (e.g. `v0.12.0-7-gabc1234`, `-dirty` with uncommitted changes) in place of `@project-version@`, so the game's addon list shows a real version; the repo's .toc files keep the token. Then tell the owner to `/reload` (restart the client if a .toc changed).
- Keep both .toc files identical (the harness checks).
- Quest facts for the route come from the Forever client reference, published free guides and in-game observations. Compare sources, write original step instructions, and record decisions in `tools/audits/`. Keep routes unverified until tested in game.
- Small, clear commits. Add a `CHANGELOG.md` section before a release.
- **Never push a tag** (that publishes to CurseForge) without the owner's explicit go-ahead.
- Keep the guide's look: parchment cards, double borders, Morpheus headings, Forever teal theme as default.
- The owner tests in game and sends screenshots: end each task with a summary, test results and a list of things to check in game.
