# Leveling Codex: notes for Claude

An in-game companion addon for the fan-made **The Leveling Codex** leveling guides, for
**World of Warcraft: Forever** (Blizzard's 2026 Classic-based client, PC/Mac only).
Published on CurseForge (project ID 1789784).

### Data.lua shape
- `spec` (e.g. "Protection"), `guide` (short guide name).
- `plan[]`: talent plan `{ name, tree, icon, max, from, to, why, more }`. Levels `from..to` each put one point into `name`; ranks add up across entries with the same name. `why` is shown at `from`, `more` on the later levels (falls back to `why` when empty).
- `train[]`: trainer visits `{ level, spells[], notes[], icons[] }`. Spell names carry ranks, e.g. `"Rend (Rank 2)"`.
- `br[]`: tip chapters ("brackets") `{ level, range, title, icon, intro, steps[], stepIcons[] }`.
- `macros[]`: `{ name, title, icon, lo, hi, body, pad, kb, tips[] }`. The same `name` appears in several level-banded versions. `pad` uses Xbox names and may contain arrows (translated at runtime).
- Guide text contains Unicode punctuation and arrows; it always goes through `plain()` / `padText()` before display.

### Modules (load order)
All files share the addon table: `local _, ns = ...`. Cross-module calls go through `ns.x()` **at call time**, so a module may call one that loads later; only values read while a file loads need load order. Never create globals (the harness fails on leaks); allowed: the SavedVariables, `LevelingCodexData`, `LevelingCodexProfessions`, `SLASH_LEVELINGCODEX1`, `BINDING_*`, `LevelingCodex_Toggle`, named frames `LevelingCodex*`.
1. `Theme.lua`: `ns.THEMES` (`forever` teal = default, `codex` gold; an external skin is added by SkinSupport.lua), `ns.C` = active palette (mutated in place by `ns.useTheme`, so `local C = ns.C` stays valid; a key the new theme doesn't name is cleared; `ns.themeKey` = the theme in use, `ns.themeVersion` bumps on each switch), `ns.rgba`, `ns.db()`/`ns.charDB()` (never nil), `ns.try` (pcall an API that may not exist), `ns.itemInfo(item)` (GetItemInfo's returns from `C_Item.GetItemInfo`, else the old global; `ns.itemInfoAPI()` = the one in use: never call `GetItemInfo` directly), timers `ns.after`/`ns.every` (C_Timer or an OnUpdate fallback), `ns.plain` (ASCII-only text), `ns.money(copper)` ("1g 20s 5c"), `ns.coins(copper)` (the same, each part in its coin's colour), `ns.thousands(n)` ("21,400"), `ns.PADS`/`ns.padText`, `ns.say`, `ns.setIcon`, `ns.fade`/`ns.fadeAccent`, `ns.placeByWindow(card, window, state)` (the talent and crafting cards: above the window, else below, else inside its top edge, clear of bars hanging off its edges, found with EnumerateFrames when it opens and 1 and 3 s later).
1b. `Art.lua` (`ns.art`): Blizzard frame art with fallbacks. `A.FILES` lists every art file; `A.hasFile` probes it once (SetTexture returns false when missing) and every piece falls back to the flat Codex look. Helpers: `A.frame` (adds `BackdropTemplate` when the client needs it), `A.backdrop(f, "dialog"|"tooltip", bg, edge)`, `A.header` (gold title banner), `A.button` (UIPanelButtonTemplate, `SetLabel`/`SetLook`), `A.segment` (a panel button for `U.segments`: lit = the panel art, a 1 px gold inner edge, gold label (moved 9 px right, clear of the tick) and the check box's tick `checkTick` when the client has it and the label fits beside it (a narrow choice keeps its label centred, lit by the edge alone); unlit = a flat `C.btnOff` plate (the template's `Left`/`Middle`/`Right` art at alpha 0) with a grey label and an accent hover; a template without those pieces dims to alpha 0.6 instead), `A.check` (UICheckButtonTemplate + label), `A.tab` (character-sheet tabs, `SetSelected`), `A.arrow` (spellbook page arrows, `codexLabel` "<"/">"), `A.portrait` (round class icon), `A.cardChrome(h)` / `A.paintCard(h, fill)` (the trainer, talent, crafting and vendor cards: tooltip border, flat edges `h.bg`/`h.edges` (always made) or external UI's panel; again before each paint, so a theme switch follows). `A.showTip(self)` (`tipTitle`, `tipText`, and `tipRows` = `{ { left, right, leftColour, rightColour } }` as `AddDoubleLine` rows, `{ text }` a wrapped note). `A.report` records what was used, for `/codex debug`. In the external UI theme (`C.eui`) no Blizzard art: `A.backdrop` takes off a border it set (`f.codexBackdrop`) and returns false, `A.header` puts the title in the shell's top bar, `A.button` is the flat button (white hover and label), `A.segment` lights in the accent without the tick, `A.check` is external UI's `S.Checkbox`, `A.arrow` and the step window's Back / Hide are its `S.PageButton` / `S.CloseButton`, `A.tab` a flat plate with an accent underline.
1c. `SkinSupport.lua` (`ns.skinSupport`, E): external UI's public skin API (`RegisterSkin("LevelingCodex", fn)`, its SKINNING_API.md, apiVersion 4; `## OptionalDeps` lists external UI; registered at load and again in `start()`). The callback (once, at PLAYER_LOGIN, only while the player has external UI's third-party skins on for the Codex) keeps the facade S and builds the external-skin palette from `S.GetPanelColor`/`S.GetAccentColor` (`E.palette()`: neutral greys, the accent for `gold`/`accent`, light `ink` on dark `parch`, `eui = true`), rebuilt by `S.OnLooksChanged` 0.4 s after the last change (a colour picker sends one per drag step, and every `ns.rebuildForTheme` makes new frames). `ns.themeName()`: with S, `db.euiTheme` or the legacy skin key; without, `db.theme` or "forever"; `ns.setTheme(name)` (Settings > Theme, a third button "External skin" while `E.available()`) writes whichever applies, so installing external UI brings its theme. `E.on()` = drawing in it now. **external UI fades every texture of a frame its Shell/Panel/Button skinned, again whenever some Blizzard windows open** (talents, professions, collections, calendar), so `E.backing(f, kind, opts)` puts `S.Shell`/`S.Panel` on a child frame (`f.euiSkin`, `codexSkin = true`, f's own frame level, nothing else on it), never on a Codex frame; pooled widgets are the Codex's flat look in the theme's colours. `E.fonts(frame)`: every font string under frame in its font (`S.Font`) or back to the one it had (`fs.codexFont`), headings (`fs.codexHead` = size, `codexHeadFlags`) through `ns.headFont()` (Morpheus, or the external UI font); once per string per theme switch, so the step window calls it every refresh. `E.font()` (Window.lua's `styleFS`; code keeps Arial Narrow), `E.scrollBar(scroll)` (`S.ScrollBar`, and an old-style slider flattened as external UI does its own), `E.call(name, ...)` (pcall'd), `E.debugLine()`.

Quest modules in .toc order:

- `QuestData.lua` defines the allowed global `LevelingCodexQuests`. Each section is playable independently and displays its verification state.
- An opportunistic item-started quest has `startItem = itemID` on its quest metadata, copied to every step. The guide waits for that item in the player's bags or for the quest to enter the log. The accept step's `item` separately provides the use button. Bag events only recalculate when the presence of a tracked starter item changes.
- `QuestAlternateData.lua`, the three 30-60 route files, `QuestDungeonData.lua`, `QuestDungeonData3060.lua`, `QuestSpecialData.lua` and the `QuestHorde*.lua` files use `QuestData.lua`'s temporary `build` helpers (`tools/questroute.py` reads the quest data files from the .toc, QuestData.lua through QuestClassData.lua). A `note` step may carry `drop = { questIDs }`: quests the player abandons there (grey dungeon pickups from an earlier band); the route audit removes them from its simulated quest log. The audit also retires a `forDungeon` pickup once the route is past that dungeon's last level + 3, because its hand-in lives in the dungeon guide. A class quest the route picks up and a class guide hands in (the Skyborne druid's Moonglade) retires the same way, past that guide's last level + 3; the class guide's later hand-in then doesn't fail. `QuestClassData.lua` consumes them last; its final block sets each special and class guide's `reward` (what finishing it gives you, shown under its title in Quests > Guides and as "You get: ..." on its page) from a `REWARDS` table by section id (a guide's own `reward` wins; sources in `tools/audits/2026-11-13-guide-rewards.md`; `quest_reward_checks()` fails a non-ASCII line, one over 60 characters or ending in a period, a reward on another kind of guide, or a `REWARDS` id that names no guide). Short class quests may be inserted after a named step. Longer chains are `side` sections with a class and optional race filter. Show class quests applies to class sections, and Missed quests can show an available class pickup even when it is grey.
- Dungeon and special guides are opt-in `side` sections with `category = "dungeon"` or `"special"`. The quest engine bookmarks the leveling route while a detour is active. Finishing or using Return to leveling resumes it. Dungeon steps have `phase = "prepare"`, `"inside"`, or `"after"`. The entry step (`type = "dungeon"`) is done while you're inside, and also once a later step of its guide is done (a run finished before the guide could see you enter). The checklist can start at any phase. An `instanceID` enables automatic entry detection, with an English name fallback when the client omits the ID. Use `uncertain` for live verification notes (data only: players never see them, like `verified`), `links` for related guide IDs, and a step's `guide` to link an outdoor step to a detour checklist (`withGuide(id, step)` in QuestData.lua, or `guide =` in an action's extra table; the step window offers Plan <guide> while it is current). ## WoW: Forever client facts (design around these)
- **Forever redrew the Eastern Plaguelands map** (quest database Forever: Tirion 5.2, 35.6; classic 7.6, 43.7; roughly x' = 0.899x - 1.58, y' = 0.898y - 3.65). Use the Forever quest database coordinates there, never classic ones. No other 30-60 map differs between the two flavours (Stormwind Keep moved too).
- `## Interface: 16001`. **Lua 5.1** (WoW flavour): no `goto`, no `//`, no integer division, no `\u{}` escapes.
- Talents use retail's **C_Traits** trait system. `GetTalentInfo`, `GetNumTalentTabs` and the Spec APIs **do not exist**. Talent window frame/button names are **unconfirmed**: keep the multi-strategy finder (known names, discovered frames, match by name then icon).
- Registering an unknown event **throws and aborts the file**: `pcall` `RegisterEvent` for anything beyond the core events.
- **Secret values.** Forever hides some numbers from addon code (your speed in flight from `GetUnitSpeed`, ...): `tonumber`, `math.*` or arithmetic on one is blocked ("numeric conversion on a secret value", a Lua error). Check `issecretvalue(v)` (may be missing on other clients) before using a number that could be secret. The mock's `MOCK.SECRET` stands for one (`tonumber` refuses it; `MOCK.runSpeed`).
- **Item data events fire for every item anyone loads** (an auction scan loads thousands): Loot.lua refreshes at once only for an item it asked for (`L.waiting`, set by LootItems.lua's `request`), folds others into one refresh 5 s later and none while `ns.auction.scanning()`. Never refresh broadly on GET_ITEM_INFO_RECEIVED / ITEM_DATA_LOAD_RESULT.
- **Item info comes from `C_Item.GetItemInfo`** (the add-ons written for Forever use it; the junk scan that asked only the global `GetItemInfo` never found a price): go through `ns.itemInfo`.
- **MERCHANT_SHOW fires before the vendor window shows** (reference guide B's Forever build waits for it too): don't treat a hidden `MerchantFrame` at that event as a closed vendor.
- **The combat log is Blizzard-only.** `RegisterEvent`/`UnregisterEvent("COMBAT_LOG_EVENT_UNFILTERED")` from an addon is blocked even inside `pcall` (the "LevelingCodex has been blocked from an action only available to the Blizzard UI" dialog, function `UNKNOWN()`). Never touch it.
- **Blocked calls are recorded.** Init.lua listens to ADDON_ACTION_FORBIDDEN / ADDON_ACTION_BLOCKED (synchronous: `debugstack` still holds the call) and keeps the last 10 in `LevelingCodexDB.blocked` with the Codex lines below the first `[C]` frame (`where`, e.g. `QuestGuide.lua:1325 < QuestGuide.lua:1378`), said once in chat and listed by `/codex debug`. taint.log stayed empty for these, so ask the owner for that chat line.
- SavedVariables are written on exit but **may not be loaded back** (beta reports). Everything must work with an empty DB; never build a feature that depends on persistence.
- Secure snippets fail. `ReloadUI()` is protected. Reading auras in combat throws.
- Macros: max **255 characters** per body, **16** per name. Macros **skip** unlearned spells but **stop** on a learned spell that isn't ready ("You can't do that yet"). `/castsequence` **stalls** on a not-ready or unlearned step; `reset=N` counts from the last press.
- The game font can't draw `→ ↑ — ×` and similar: **all runtime text must be ASCII** (route guide text through `plain()`).
- Missing texture paths render **green**: always use `setIcon`, or check `SetTexture`'s return value and fall back.
- **Looping animations jump.** The arrival bob (a Translation looping `BOUNCE`) visibly jumped at its turns in game. Draw anything that loops (bobs, pulses) from `GetTime()` in an OnUpdate as a cosine, like the arrow's `bob()` and the taxi ring; keep AnimationGroups for one-shots, and give a fade-out that hides in `OnFinished` `SetToFinalAlpha(true)`.
- Assume any non-core API may be missing: guard with existence checks and `pcall`.

## Working rules
- Run the harness before every commit. It must pass with no Lua errors, no non-ASCII runtime text and no leaked globals.
- When a bug is reported from the game, first add a scenario that reproduces it.
- **Guide facts come from the game, not memory.** Before changing a talent reason, macro or trainer line, check it with `python tools/gamedata.py spells|tree|review|packet CLASS`. After a Forever patch or hotfix (or a Game data PR), follow `tools/UPDATING.md`.
- **In-game testing: install straight into the owner's game, never hand over a zip.** After the harness passes, run `python tools/install.py`. It copies the build into `C:\Program Files (x86)\World of Warcraft\_forever_\Interface\AddOns\LevelingCodex` (override with an argument or `LEVELINGCODEX_ADDONS`), removes stale `.lua`/`.xml` from older builds, leaves other files alone and verifies every copy. The installed .toc files get `git describe` (e.g. `v0.12.0-7-gabc1234`, `-dirty` with uncommitted changes) in place of `@project-version@`, so the game's addon list shows a real version; the repo's .toc files keep the token. Then tell the owner to `/reload` (restart the client if a .toc changed).
- Keep both .toc files identical (the harness checks).
- Quest facts for the route come from the Forever client reference, published free guides and in-game observations. Compare sources, write original step instructions, and record decisions in `tools/audits/`. Keep routes unverified until tested in game.
- Small, clear commits. Add a `CHANGELOG.md` section before a release.
- **Never push a tag** (that publishes to CurseForge) without the owner's explicit go-ahead.
- Keep the guide's look: parchment cards, double borders, Morpheus headings, Forever teal theme as default.
- The owner tests in game and sends screenshots: end each task with a summary, test results and a list of things to check in game.
