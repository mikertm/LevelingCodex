# Leveling Codex: notes for Claude

An in-game companion addon for the fan-made **The Leveling Codex** leveling guides, for
**World of Warcraft: Forever** (Blizzard's 2026 Classic-based client, PC/Mac only).
Published on CurseForge (project ID 1789784).

## Files

| File | What it is |
|---|---|
| `LevelingCodex.toc`, `LevelingCodex_Camelot.toc` | Load order. **Must stay byte-identical.** Keep `## Version: @project-version@` (the packager fills it from the tag). |
| `Data.lua` | **Generated** from the guide pages: `LevelingCodexData[CLASS_TOKEN] = { spec, guide, plan, train, br, macros }`. Small hand fixes are OK, but keep its shape and list every data change in your summary so the owner can mirror it in the guides. |
| `ProfessionData.lua` | **Hand-written** profession guides: `LevelingCodexProfessions[PROF] = { name, skillLine, icon, tiers, steps, notes }` (a tier's `where` over 60 characters needs a `short` for the one-line banner rows) (`BLACKSMITHING`, `MINING`; Mining adds `veins`, `smelt`, `camp`). Each recipe's `spell`, `yellow`, `grey`, `mats`, `icon` (and `makes`, when a later step uses the product) must equal the game reference (the harness checks); `learn`, sources, `extra` (quest turn-ins for the shopping list), tiers and zones are guide text (server-side facts). The client's `MinSkillLineRank` is in the reference as `min`: the audit warns when `learn` is lower, and the route starts steps at the higher value. |
| `Theme.lua` … `Init.lua` | Addon code, one module per file, loaded in .toc order (see below). |
| `Bindings.xml` | Key binding "Open or close the Codex" (auto-loaded by the client, not listed in the .toc). |
| `CHANGELOG.md` | Becomes the CurseForge release notes (`.pkgmeta` `manual-changelog`). Add a section before every release. |
| `CURSEFORGE_DESCRIPTION.md`, `README.md`, `RELEASING.md` | Docs, not packaged. |
| `.pkgmeta`, `.github/workflows/release.yml` | BigWigsMods packager. Pushing a `v*` tag builds and uploads to CurseForge. |
| `tests/` | Headless test harness (Python + lupa, Lua 5.1). Not packaged. |
| `tools/gamedata.py` | What the game itself says. Downloads the Forever client's tables from wago.tools (product `wowf`, cached in `tools/.cache/`), builds `tools/reference/forever.json` (talent trees with tab/row/col/max/points needed/prereqs/tooltip per rank; class and pet spells with rank/level/cost/cooldown/tooltip; Mining and Blacksmithing recipes with colours/reagents/product/icon/plan (the item whose trigger-6 effect teaches it), `auto` (learned with the profession), `skillups` when not 1, and `clashes`: names the game gives to more than one spell), diffs two references, audits `Data.lua` and `ProfessionData.lua` against it (`update`, `audit` and the daily report cover both). `packet CLASS` prints a class's whole guide next to the game data for review; `recipes PROFESSION [NAME]` lists recipes, `profs [PROFESSION]` the route next to the game. |
| `tools/reference/forever.json` | The committed game reference. The harness checks `Data.lua` against it offline; its git diff after an update is the list of game changes. |
| `tools/UPDATING.md`, `.github/workflows/gamedata.yml` | The update routine after a patch/hotfix, and a daily workflow that opens a PR when a new Forever build appears. |
| `tools/audits/` | One file per audit: every Data.lua change with its reason and before/after, for mirroring into the guide pages. |

### Data.lua shape
- `spec` (e.g. "Protection"), `guide` (short guide name).
- `plan[]`: talent plan `{ name, tree, icon, max, from, to, why, more }`. Levels `from..to` each put one point into `name`; ranks add up across entries with the same name. `why` is shown at `from`, `more` on the later levels (falls back to `why` when empty).
- `train[]`: trainer visits `{ level, spells[], notes[], icons[] }`. Spell names carry ranks, e.g. `"Rend (Rank 2)"`.
- `br[]`: tip chapters ("brackets") `{ level, range, title, icon, intro, steps[], stepIcons[] }`.
- `macros[]`: `{ name, title, icon, lo, hi, body, pad, kb, tips[] }`. The same `name` appears in several level-banded versions. `pad` uses Xbox names and may contain arrows (translated at runtime).
- Guide text contains Unicode punctuation and arrows; it always goes through `plain()` / `padText()` before display.

### Modules (load order)
All files share the addon table: `local _, ns = ...`. Cross-module calls go through `ns.x()` **at call time**, so a module may call one that loads later; only values read while a file loads need load order. Never create globals (the harness fails on leaks); allowed: the SavedVariables, `LevelingCodexData`, `LevelingCodexProfessions`, `SLASH_LEVELINGCODEX1`, `BINDING_*`, `LevelingCodex_Toggle`, named frames `LevelingCodex*`.
1. `Theme.lua`: `ns.THEMES` (`forever` teal = default, `codex` gold), `ns.C` = active palette (mutated in place by `ns.useTheme`, so `local C = ns.C` stays valid; `ns.themeVersion` bumps on each switch), `ns.rgba`, `ns.db()`/`ns.charDB()` (never nil), `ns.try` (pcall an API that may not exist), timers `ns.after`/`ns.every` (C_Timer or an OnUpdate fallback), `ns.plain` (ASCII-only text), `ns.PADS`/`ns.padText`, `ns.say`, `ns.setIcon`, `ns.fade`/`ns.fadeAccent`, `ns.placeByWindow(card, window, state)` (the talent and crafting cards: above the window, else below, else inside its top edge, clear of bars hanging off its edges, found with EnumerateFrames when it opens and 1 and 3 s later).
1b. `Art.lua` (`ns.art`): Blizzard frame art with fallbacks. `A.FILES` lists every art file; `A.hasFile` probes it once (SetTexture returns false when missing) and every piece falls back to the flat Codex look. Helpers: `A.frame` (adds `BackdropTemplate` when the client needs it), `A.backdrop(f, "dialog"|"tooltip", bg, edge)`, `A.header` (gold title banner), `A.button` (UIPanelButtonTemplate, `SetLabel`/`SetLook`), `A.check` (UICheckButtonTemplate + label), `A.tab` (character-sheet tabs, `SetSelected`), `A.arrow` (spellbook page arrows, `codexLabel` "<"/">"), `A.portrait` (round class icon). `A.report` records what was used, for `/codex debug`.
2. `Guide.lua`: lookups into `ns.D` (this class's guide, set at login): `talentAt`, `trainAt`, `nextTrain`, `bracketFor`, `macrosFor`, `comingMacros`. All cope with `ns.D == nil`.
2b. `Professions.lua`: the profession guides (`ns.P` = `LevelingCodexProfessions`, `ns.PROF_ORDER`). `ns.profSkill(key)` (GetProfessions, else the classic skill list; nil = not learned/unknown; a closed heading in the classic list keeps the last skill seen this session, or returns `nil, nil, true` = "not seen"), `profStep`, `profNext`, `expectedCrafts`/`craftsLeft` (1 per point below yellow, then `(grey - s) / (grey - yellow)`), `profShopping`, `profTier`/`profTierDue` (`"train"`/`"cap"`), `veinColor` (orange < skill+25 < yellow < +50 < green < +100), `profZones` (faction, `All`, Skyborne isle). Skill-ups (SKILL_LINES_CHANGED / CHAT_MSG_SKILL / TRADE_SKILL_UPDATE, else a 1 s poll) are compared with the last reading this session: `ns.profCardRows` -> `ns.showCard` only at a new step, a tier due, a cap, a new vein (`db.noProfCards`; the card's subtitle is your tier). `ns.profLevelRows(level)`: training a level-up opens (skill already there), as rows for the level-up banner and chat. TRAINER_SHOW records requirements that differ from the guide's `learn` (`ns.trainerDebugLines`).
3. `Macros.lua`: `ns.setupMacros(onlyExisting)`. A macro is "ours" if it's in `LevelingCodexCharDB.made` **or its body matches a guide version** (so auto-update survives lost SavedVariables). Combat: a manual setup is queued as "full", a level-up refresh as "refresh" (never creates macros). Failures open the copy box.
4. `Banner.lua`: level-up chat (`ns.levelUpMessage`) and the banner (`ns.showToast(level, force, test)`, `ns.showCard(title, sub, rows, onClick)` for other cards shown right away, `ns.setToastUnlocked`, `ns.placeToast`, `ns.getToast`, `ns.dropToast`).
5. `Window.lua`: the `/codex` window: pooled widgets (`take`/`releaseAll`), drawing helpers (`T`, `rect`, `box`, `icon`, `btn`, `chip`), `renderers[tab]` (level/talents/trainer/macros/tips/settings), per-tab scroll memory, the talent tree (`talentModel`, `layoutTree`: game layout from `ns.traitLayout()` else tiers from the plan), controller/keyboard drawing (`parsePad`, `padCombo`, `keyCombo`, `controllerMock`, `keyboardMock`; glyphs on the `top` layer above icons), `ns.rebuildForTheme`, `ns.openTab`, `ns.toggleWindow`, the copy box `ns.showMacroCopy(m, list)`, Esc/controller close. Other files add tabs with `ns.addTab(key, label, renderer)` (before Settings) and draw with `ns.ui` (`W`, `T`, `rect`, `box`, `plate`, `icon`, `btn`, `check`, `hit`, `sectionTitle`, `goldRuleAt`, `refresh`).
5b. `ProfessionTab.lua`: the Professions tab: Blacksmithing/Mining switch, your skill, the step to do now (or one clicked in the route) with materials against your bags, the training card, the route, the shopping list to 300, veins with zones, camp objects. `ns.profTabShow(key)`.
6. `Minimap.lua`: `ns.updateMini`.
7. `TalentGuide.lua`: 0.25 s ticker. Shows only while there are unspent points (`C_Traits` tree currency, else `UnitCharacterPoints`; unknown = show) and traces the next unspent point in the plan (`10 + points spent`). The trace copies the button's own border art (`StateBorder`/`Border`/... atlas or file) so it matches circle/square/choice nodes; with only a mask it draws a round glow, else a box. Finds the window (`TALENT_ROOTS`, then window-sized frames named `*Talent*`/`*Trait*` found by `discoverRoots` on toggle hooks and talent-addon loads), then the button by name (trait APIs) or icon. Once found it only re-checks the cached button (pooled buttons get reused); misses back off up to 8 s. Hides on the window's `OnHide`. Never treat `LevelingCodex*` frames as a window.
7a. `ProfessionGuide.lua`: the crafting window guide (`db.noCraftGuide`). Active from TRADE_SKILL_SHOW until TRADE_SKILL_CLOSE (else polling; the event may come before the window shows, so it re-discovers windows for 10 s). Finds the window (`TradeSkillFrame`, `ProfessionsFrame`, `CraftFrame`, then discovered `*TradeSkill*`/`*Profession*` frames, never `LevelingCodex*`), the profession (`GetTradeSkillLine` or `C_TradeSkillUI.GetBaseProfessionInfo`, "Smelting" = Mining), the recipe (`GetTradeSkillInfo`, then `C_TradeSkillUI.GetRecipeInfo`: colour, numAvailable; the classic list only holds what the window shows) and its row by text (colour codes, `[N]` counts and padding stripped; a button first, never the details pane; while it's out of view the search backs off 0.5, 1, 2 s). Hides on the window's `OnHide`. Not in the list: `IsPlayerSpell` tells "filtered" from "not learned" (with the step's alternative). Show it (always offered while the row is out of view) selects the recipe and brings its row into view: the classic list (`FauxScrollFrame_SetOffset`), else a ScrollBox's `ScrollToElementDataByPredicate` (Forever's own window), else positions tried on the window's scroll controls (scroll percentage, sliders, scroll frames) outwards from the recipe's place in the list; then it clicks the row so the window's own selection follows, and `/codex debug` says what it did (tests: `makeCraftWindow:scrollbox`). Outlines the row (`LevelingCodexCraftTrace`) and shows `LevelingCodexCraftHint` (not learned / grey: next step / Show it when scrolled off). Mining picks the step's smelt you can know with the best chance (counted only while orange, else its chance; none: "mine instead" and when the next smelt opens). `ns.craftDebugLines`.
7b. `Tracking.lua`: keeps Find Herbs / Find Minerals on (`db.noAutoTrack` turns it off). Reads the minimap tracking list (`C_Minimap`, else the classic globals; either return style), matches by spell ID, name or icon. Restores 2 s and 6 s after PLAYER_ENTERING_WORLD / PLAYER_ALIVE / PLAYER_UNGHOST and when a new gathering tracker is learned; at login re-toggles one that already looks on. Skips while dead, defers combat to PLAYER_REGEN_ENABLED, never overrides another active spell tracking, remembers the last non-empty set on (`charDB.gatherTrack`). No list API: one chat reminder. `ns.restoreTracking`, `ns.trackingDebugLines`.
8. `Init.lua`: events (`start()` is idempotent: PLAYER_LOGIN, retried at PLAYER_ENTERING_WORLD), lost-SavedVariables detection (`ns.settingsLost`), key binding globals, `/codex`.

## WoW: Forever client facts (design around these)
- `## Interface: 16001`. **Lua 5.1** (WoW flavour): no `goto`, no `//`, no integer division, no `\u{}` escapes.
- Talents use retail's **C_Traits** trait system. `GetTalentInfo`, `GetNumTalentTabs` and the Spec APIs **do not exist**. Talent window frame/button names are **unconfirmed**: keep the multi-strategy finder (known names, discovered frames, match by name then icon).
- Registering an unknown event **throws and aborts the file**: `pcall` `RegisterEvent` for anything beyond the core events.
- SavedVariables are written on exit but **may not be loaded back** (beta reports). Everything must work with an empty DB; never build a feature that depends on persistence.
- Secure snippets fail. `ReloadUI()` is protected. Reading auras in combat throws.
- Macros: max **255 characters** per body, **16** per name. Macros **skip** unlearned spells but **stop** on a learned spell that isn't ready ("You can't do that yet"). `/castsequence` **stalls** on a not-ready or unlearned step; `reset=N` counts from the last press.
- The game font can't draw `→ ↑ — ×` and similar: **all runtime text must be ASCII** (route guide text through `plain()`).
- Missing texture paths render **green**: always use `setIcon`, or check `SetTexture`'s return value and fall back.
- Assume any non-core API may be missing: guard with existence checks and `pcall`.

## Tests
- `python tests/run.py` (needs `pip install lupa`; ~25 s, runs in parallel). `-k WARRIOR/full` filters runs, `-v` prints all data warnings.
- `tests/wowmock.lua` is the mocked client. Strict on purpose: unknown events, templates, scripts or methods throw; `SetPoint` refuses self/looped anchors; `CreateMacro` enforces the 255/16 limits and combat lockdown. `minimal = true` removes optional APIs (C_Timer, C_Spell, GetFileIDFromPath, EnumerateFrames, hooksecurefunc, GetMacroInfo, gradients, gamepad...).
- `tests/scenarios.lua` only drives what a player or the client can reach (events, `/codex`, clicks, drags, named frames), so it survives refactors. Each run (class x full/minimal x main/icon/persisted/lost-savedvars) starts a fresh Lua state.
- Also checked: both .toc files identical, `@project-version@`, Data.lua shape, talent plan covers 10-60, macro limits, and a lint for `/castsequence` steps not yet learned at the macro's first level (warnings, not failures). `prof_shape_checks()`: ProfessionData.lua's fields, ASCII text, Mining steps naming real veins/smelts.
- Profession scenarios: `skills:BS;87;150,MI;140;225:professions` sets skills (`skilllines` = only the classic skill list; `skillsClosed` / `MOCK.skillsCollapsed` closes its heading); `MOCK.setSkill` fires the skill events; `makeCraftWindow[:retail]` builds a crafting window (`MOCK.trade`); `MOCK.trainer` feeds TRAINER_SHOW.
- **Game checks** (`game_checks()`, via `tools/gamedata.py audit` and the committed `tools/reference/forever.json`): fail on a talent that isn't in the class tree, a wrong tab or rank count, a point spent before its row is open or its prerequisite is maxed, a trainer rank that doesn't exist or isn't trainable yet, a macro spell the class doesn't have or a `/castsequence` step learned after the macro's first level. Warn on levels in guide text like "Swipe (16)" that differ from the game, icons that differ, spells listed earlier than the game teaches them. Professions (`audit_professions`): fail on a recipe not on the skill line, colours/reagents/spell that differ, a step that goes grey before it ends, gaps between 1 and 300, a tier that can't be trained before the previous cap; warn on mostly-green steps, icons, `learn` after a step starts, a step naming a recipe the game has more than once, a "trainer" step whose recipe comes from a plan, a `learn` that differs from its plan's skill, "Known when you learn" that doesn't match `auto`, points per craft other than 1. `tool_checks()`: `update`/`audit` and the daily report include the profession audit.

## Working rules
- Run the harness before every commit. It must pass with no Lua errors, no non-ASCII runtime text and no leaked globals.
- When a bug is reported from the game, first add a scenario that reproduces it.
- **Guide facts come from the game, not memory.** Before changing a talent reason, macro or trainer line, check it with `python tools/gamedata.py spells|tree|review|packet CLASS`. After a Forever patch or hotfix (or a Game data PR), follow `tools/UPDATING.md`.
- **In-game testing: install straight into the owner's game, never hand over a zip.** After the harness passes, run `python tools/install.py`. It copies the build into `C:\Program Files (x86)\World of Warcraft\_forever_\Interface\AddOns\LevelingCodex` (override with an argument or `LEVELINGCODEX_ADDONS`), removes stale `.lua`/`.xml` from older builds, leaves other files alone and verifies every copy. Then tell the owner to `/reload` (restart the client if a .toc changed).
- Keep both .toc files identical (the harness checks).
- Small, clear commits. Add a `CHANGELOG.md` section before a release.
- **Never push a tag** (that publishes to CurseForge) without the owner's explicit go-ahead.
- Keep the guide's look: parchment cards, double borders, Morpheus headings, Forever teal theme as default.
- The owner tests in game and sends screenshots: end each task with a summary, test results and a list of things to check in game.
